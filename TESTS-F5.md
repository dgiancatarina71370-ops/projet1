# Recette F5 — Documents versionnés et figés (version 0.15.0, schéma 8)

**Ce que F5 change** : un livrable ne s'exporte plus directement. L'écran **Livrables** génère l'aperçu comme avant, mais son bouton devient **Enregistrer comme document** : il enregistre une photographie datée du livrable (contenu Markdown figé, options utilisées, liste figée des éléments) en **Brouillon**. Le nouvel écran **Documents** (section Pilotage, après Livrables) liste les documents du **projet actif** : version, état, origine, date ; le détail montre les options, la liste figée et l'aperçu, et exporte en Markdown, HTML et Word **depuis le contenu figé**, jamais depuis les données courantes. Régénérer un livrable dont le contenu a changé crée la **version suivante** ; la précédente passe à l'état **Remplacé**. Contenu identique à la dernière version : rien n'est créé. Un fichier exporté d'un document généré porte, sous le titre, une ligne « Document : version N, statut » et la version dans son nom. La carte « Exporter un livrable » **quitte l'écran Technique** ; les documents importés de la V1 deviennent consultables et exportables dans Documents. **Migration 8 : le schéma passe de 7 à 8.** 16 écrans.

**Précaution, plus stricte que d'habitude : ce lot modifie le schéma de ta base.** Prépare deux dossiers, `Test-avant` (exécutable **0.14.0**) et `Test-F5` (exécutable **0.15.0**), chacun avec **sa propre copie** de `BAMentorData`. **Ne lance jamais la 0.15.0 sur ton dossier d'origine avant la fin de la recette.** Une fois une base migrée en schéma 8, la 0.14.0 refuse de l'ouvrir ; le seul retour en arrière est une sauvegarde d'avant la migration. Les chiffres ci-dessous valent pour le **projet d'exemple neuf, non modifié** (crée-le dans une copie vide si besoin) ; les tests 4 à 12 se jouent **dans l'ordre**.

**Non vérifiable de mon côté** : la migration sur ta vraie base et avec le moteur de l'application (mes tests utilisent un moteur SQLite de test), le rendu réel et les clics, les fichiers Word et HTML ouverts dans leurs logiciels, la boîte « Enregistrer sous… », le contrôle réel des types React, le Rust, l'exécutable, le volume des documents sur une grosse base.
